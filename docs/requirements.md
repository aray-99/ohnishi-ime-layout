# 要件定義

## 1. 目的

Windows上の日本語タイピングを大西配列で最適化する。

本プロダクトは、常時大西配列を実現することを目的としない。
英数入力とショートカットのQWERTY操作を維持しながら、日本語ローマ字入力に
限定して大西配列を適用する。

## 2. 利用者と運用

- 主利用者は個人利用者1名
- スクリプトは基本的に常駐
- ソースコードと文書はGit/GitHubで管理
- 将来、他の利用者が使用できる形で公開する可能性がある
- 小規模プロダクトに見合う軽量な文書・試験・保守を行う

## 3. Release 1 必須要件

### R1-01 実行環境

- AutoHotkey v2.0安定版を使用する
- Windows 10または11を対象とする
- 初期の正式対象IMEはWindows標準日本語IMEとする

### R1-02 常駐

- 通常利用時はバックグラウンドで常駐できる
- Windowsログイン時の自動起動手順を提供する
- 多重起動による二重変換を防止する

### R1-03 大西配列の適用

大西配列は、日本語IMEがローマ字を日本語へ変換するかな・カナ系入力モードの
場合にだけ有効にする。

日本語IMEが次の英数入力モードにある場合はQWERTYとする。

- 半角英数
- 全角英数

IME状態を安全に判定できない場合もQWERTYとする。

### R1-04 ショートカット

Ctrl、Alt、Windowsキーのいずれかを伴う操作は、IME状態にかかわらずQWERTYを
優先する。

既知のショートカットを個別列挙して対応するのではなく、修飾キーを伴う文字変換
全体を除外する設計を優先する。

利用者のJIS環境では、日本語入力中も次が通常操作で動作すること。

- `Ctrl + +`
- `Ctrl + -`

上記の`+`に追加のShift操作を要求しない。

### R1-05 Shift入力

Shiftだけを伴う場合は大西配列を維持し、変換後の大文字または対応する記号を
入力する。

### R1-06 高速入力

文字キー同士に特殊な同時押しの意味を与えない。

次を使用しない。

- 文字キーのコード判定
- 時間窓による文字決定
- tap/hold
- 通常文字のキーアップ待ち
- 通常文字の意図的な遅延

文字キーの押下時間が重なっても、通常の連続入力として扱う。

### R1-07 運用操作

少なくとも次を提供する。

- 配列変換の有効・無効
- 状態表示
- 再読み込み
- 緊急終了
- アプリケーション除外

### R1-08 安全性

- スクリプト終了時は通常のQWERTY入力へ戻る
- 修飾キーを残留させない
- 生成したキーを再変換しない
- キー入力や文字内容をログへ保存しない
- 外部通信を行わない
- 原則として管理者権限を要求しない

### R1-09 個人設定

CapsLockと半角/全角の交換はRelease 1のCoreへ含めない。

当面はPowerToys側の設定を利用し、AutoHotkeyとPowerToysが同じキーを同時に
リマップしない。

必要になった場合だけ、公開Coreとは別の任意Personalモジュールへ移す。

## 4. 大西配列

```text
物理位置: Q W E R T Y U I O P
出力文字: Q L U , . F W R Y P

物理位置: A S D F G H J K L ;
出力文字: E I A O - K T N S H

物理位置: Z X C V B N M , . /
出力文字: Z X C V ; G D M J B
```

## 5. Release 2 要件候補

US物理キーボードを、日本語IMEを維持しながら利用しやすくする互換レイヤーを
追加する。

- `JIS` / `US_COMPAT`の手動プロファイル切替え
- USキートップに近い記号入力
- LaTeXで頻用する記号を優先
- 特にバックスラッシュを迷わず入力できる
- 頻繁なWin+Space切替えを不要にすることを目標とする
- ショートカットとの競合を検証する

初期優先記号：

```text
\ [ ] { } ( ) - _ = + ` ~
```

自動デバイス識別は初期要件ではない。

## 6. 対象外

- 独自キーボードドライバー
- かな入力配列
- macOS/Linux
- ゲームマクロ
- 文字キーのコード入力
- 企業向け集中管理
- 全IMEと全アプリケーションの完全保証
- 入力内容の収集
